# Ninety Launch

![Ninety Launch](./assets/images/9xl.png)

Ninety Launch (9xL) is a simple Windows launcher designed to centralize your Windows 9x games, and provide an interface to install, launch, and manage them. It is designed to be a simple, lightweight, and easy-to-use launcher.

## Planned Features

- Pulling and extracting DOS files from GOG installers
- Automatically configuring `PIF` files with the correct requirements for each game and your system
- Installing and bringing under management any games in which you own physical media for, such as CD-ROMs or floppy disks

## Contributing

Developers are welcome to contribute to Ninety Launch. Please fork the repository and submit pull requests for any features or bug fixes you would like to contribute.

### Building the project

Prerequisites:

- Install Open Watcom V2.0 and add it to your PATH (This project assumes it will be located at `C:/WATCOM` and that the `wmake` command will be available in your PATH)
- Install CMake and add it to your PATH
- Running Windows 10 or later is recommended, as this project is designed to be built and run on modern Windows systems, it has not been tested on WINE or other compatibility layers.

VSCode:

1. Open the project in VSCode
2. Install the C/C++ extension for VSCode if you haven't already
3. Open the command palette (Ctrl+Shift+P) and select "CMake: Configure"
4. Run "CMake: Build" to build the project

### Debugging

We're leveraging Open Watcom V2.0 in this project, so debugging is a bit different than what you may be used to. You can use the Open Watcom debugger `wd` to debug the project. You can also use the `wmake` command to build and run the project in debug mode.

#### Remote Debugging

1. Copy `tcpserve`, `std.dll`, and `wd` from the Open Watcom installation directory to a directory on your remote system running Windows 9x. You can find these files in the `binnt` directory of your Open Watcom installation.
2. Run `tcpserve` on the remote system to start the TCP server for remote debugging.
3. (Optional) If you would like to add `tcpserve` to startup on the remote system, you can add it to the `Startup` folder in the Start Menu.
4. When you are ready to debug, run `wd` on your development system and connect to the remote system like so:

```cmd
conhost.exe "$env:WATCOM\binnt\tcpserve.exe" '/tr=tcp;<remote_ip_address>:<port>' /download build\win9x-debug\*.exe
```

_We recommend using `conhost.exe` to run the debugger as powershell and the Windows Terminal seem to not handle the debugger TUI correctly._

### Anti-AI policy

We do not accept contributions that are entirely generated by AI tools/LLMs. We will accept contributions that have been written with the assistance of AI tooling/LLMs, but the contributor must be able to demostrate they have a complete understanding of the code they are submitting. We encourage contributors to use AI tools/LLMs to assist with research into the problem they are trying to solve, but the code itself must be written by a human.

We understand that this may be a controversial policy, but we believe it is important to maintain the integrity of the project and the quality of the codebase.
